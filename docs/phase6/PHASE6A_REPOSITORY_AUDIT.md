# DietShift Atlas — Phase 6A Repository & Documentation Audit (WP1)

**Audit Date:** 2026-11-17  
**Audited Baseline:** `v5.2.0-phase5c`  
**Repository:** [`aminezghi/dietshift-atlas`](https://github.com/aminezghi/dietshift-atlas)  
**Audit Scope:** Exhaustive static and structural reconciliation across TypeScript analytical engines, React components, Python build pipelines, 19 ZSTD Parquet tables, runtime JSON bundles, CI/QA suites, citations, and documentation files (`AGENTS.md` frozen-code rules honored: zero analytical code or datasets modified during this audit).

---

## 1. Executive Summary

DietShift Atlas at `v5.2.0-phase5c` operates as a client-side Vite + React 19 + TypeScript + ECharts + DuckDB-Wasm computational food-systems observatory backed by **19 ZSTD-compressed Parquet tables (17,627 total rows; 944,545 bytes)** and **26 runtime/reference JSON files** in `public/data/`. Phases 3A–5C substantially hardened the core TypeScript analytical engines (`src/analytics/*`), eliminated unit conflation and silent numeric imputations in the Researcher Sandbox and Open Food Facts snapshots, added fail-fast JSON–Parquet parity checks, and established a 5-stage Playwright + Vitest + Pytest + Oxlint QA gate (`scripts/run_qa_gate.py`).

However, inspecting the complete repository reveals a stark split between the **remediated software core** and **unreconciled peripheral documentation, academic manuscript drafts, citation metadata, and external dataset licensing records**:

1. **Critical Academic Manuscript Obsolescence (`paper/*`):** All manuscript files (`paper/DIETSHIFT_ATLAS_ACADEMIC_PAPER.md`, `.html`, `.docx`, `paper/main.tex`, `paper/references.bib`) still report retracted claims removed in Phase 4A/5A (`Google TimesFM 200M`, `89.4% MAE reduction`, `ml_timesfm_forecasts.parquet`, `12` Parquet datasets, `DuckDB-Wasm 1.28`, `151,203` FMCG SKUs).
2. **Public Documentation & Citation Metadata Drift:** `CITATION.cff` (`version: "3.4.1"`, `timesfm` keyword), `docs/PUBLIC_GUIDE.md` (`Google TimesFM 2.0`, `12 Observatories`, `11` Parquet tables, `151,203` products), `src/App.tsx:1099` (BibTeX copy string hardcoded to `version = {4.0.0}`), `README.md` (prior to Phase 6A update), `docs/development/DATA_SOURCES.md` (`18` tables; misclassifies `Poore & Nemecek` and `NHANES` as `Observed`), `docs/development/DATA_DICTIONARY.md` (`18` tables header), and `docs/development/DATA_PIPELINE.md` (`18` tables) disagree with the verified `datasets_registry.json` (`19` tables, `17,627` rows) and engine implementations.
3. **Unverified & Ambiguous Dataset Redistribution Rights:** At least six registry entries (`gi_terroir_registry` Qualigeo records, `gs1_immagino_observatory`, `pan_eu_retail_scanner`, `time_use_cooking_friction`, `cultural_climate_inertia` ESS overlap, `social_discourse_velocity` RSS/HN publisher snippets) plus two non-registry runtime assets (`public/data/world.geojson`, hardcoded `COUNTRY_PROFILES` in `src/types/research.ts`) carry incomplete, ambiguous, or potentially non-commercial/restricted redistribution terms.
4. **Reproducibility & Pipeline Hygiene Gaps:** `requirements.txt` omits runtime/test packages (`pytest`, `pyarrow`, `numpy`), legacy fallback-imputing Python scripts (`scripts/fetch_live_data.py`, `scripts/build_consumer_pulse_and_scale_off.py`) remain alongside repaired scripts (`scripts/refresh_off_clean.py`), and `scripts/build_nsi_and_ml_parquet.py:12` still prints `TIMESFM 2.0 BACKTESTING` despite executing classical ETS/Ridge/Drift backtesting.

### 3.2 Hidden / Legacy Codebase & Modeling Risks Not Yet Resolved

1. **Coexistence of Superseded Fallback-Imputing Pipeline Scripts:**
   - [`scripts/build_consumer_pulse_and_scale_off.py`](../../scripts/build_consumer_pulse_and_scale_off.py) (`L99–100+`) and [`scripts/fetch_live_data.py`](../../scripts/fetch_live_data.py) (`L44–51`) still contain legacy default nutriment/Eco-Score imputation logic. They were superseded operationally by [`scripts/refresh_off_clean.py`](../../scripts/refresh_off_clean.py) (which preserves missing nutriments and NOVA/Eco-Score as `NULL`), yet re-running the wrong legacy script would re-inject fabricated defaults until `build_data_infrastructure.py` flags the imputation signature.
   - [`scripts/build_nsi_and_ml_parquet.py:12`](../../scripts/build_nsi_and_ml_parquet.py#L12) prints `TIMESFM 2.0 BACKTESTING` in its console banner even though lines `806–1099` actually run statistical backtesting and explicitly unlink legacy `ml_timesfm_forecasts.*` files (`L1080`).
2. **Undocumented / Stylized Compile-Time Baselines:**
   - **`COUNTRY_PROFILES` (`src/types/research.ts`, `25` jurisdictions):** Manually compiled dietary baselines (EAT-Lancet intake indices, daily kg CO₂eq, daily liters water, daily m² land, daily basket EUR) have **no per-country primary source citations, reference years, or confidence bounds** documented in `datasets_registry.json` or inline comments. Policy intervention simulation (`policyScenarioModel.ts v5.1.0-phase5a`) runs directly over these 25 profiles using heuristic slopes (`ANALYST_POLICY_COEFFICIENTS`).
   - **Stylized Analytical Tables:** `efsa_foodex2_surveys.parquet` (`1,080` rows, `v2.0-stylized`), `time_use_cooking_friction.parquet` (`60` rows, `v1.0-stylized`), `consumer_behavior_pulse.parquet` (`8` rows, `v3.5`), and non-Italian rows of `pan_eu_retail_scanner.parquet` (`88` rows, `v3.5`) are derived from curated country/quintile multipliers or report transcriptions—not respondent-level survey microdata or live retail scanners. While disclosed in `datasets_registry.json` and `DataNatureBadge`, researchers must not treat them as direct microdata samples.
3. **Browser vs. Pipeline Runtime Dependency Gap:**
   - [`requirements.txt`](../../requirements.txt) (`29` pinned scraping/DuckDB packages) omits `pytest`, `pyarrow`, and `numpy`, even though `tests/run_qa_gate.py`, `scripts/build_deep_empirical_pipeline.py`, and `scripts/build_nsi_and_ml_parquet.py` import them directly. GitHub Actions (`qa-gate.yml`, `deploy.yml`) installs `pytest duckdb pyarrow playwright` explicitly via `pip install`, bypassing `requirements.txt`.
   - `public/data/datasets_registry.json` records `freshness_days` statically relative to generation time (`2026-11-16T14:32:17Z`), which ages passively in static browser deployments rather than reflecting live clock drift.
4. **Live Browser DuckDB-Wasm E2E Execution Scope:**
   - As transparently documented in `PHASE5C_QA_IMPLEMENTATION_REPORT.md`, Playwright (`tests/e2e/test_atlas_e2e.py`) verifies clean mounting of Sections `V` (`DuckDBParquetWorkbench`) and `XII` without runtime errors, while SQL–Parquet schema/value parity is tested in Python (`tests/test_empirical_pipeline.py`) rather than running full 35.91 MB Wasm SQL queries inside CI Chromium.
5. **External Dataset Redistribution & License Verification Gaps:**
   - See full breakdown in [`docs/DATA_PROVENANCE_AND_LICENSING.md`](../DATA_PROVENANCE_AND_LICENSING.md). Multiple datasets rely on third-party terms requiring pre-release legal/attribution sign-off (Qualigeo, GS1 Immagino / Pan-EU benchmark, MTUS/IPUMS registration limits, ESS `CC BY-NC-SA` non-commercial constraint risk, HN/Google News publisher metadata, un-tracked `world.geojson`).
